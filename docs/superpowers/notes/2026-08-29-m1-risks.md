# M1 risks, carried out of M0

> **Status:** all four items are CLOSED. Items 1-3 in `124f3bc`, item 4 across
> `fb3c5ac` (Package.swift parsing) and `c8f28b4` (every Apple-only module). The
> triage table in section 5 still stands.

Written at M0 close, from the final whole-milestone review. These are the things in the
finished shell that will make M1 (Notes: GRDB, an `NSTextView`-backed editor, note tabs,
FTS search) harder than it needs to be. Ordered by how early they bite.

## 1. ~~`shouldCollapse` becomes wrong the moment an editor exists~~ — CLOSED `124f3bc`

`PanelMachine.shouldCollapse` honours only three of its six signals — `isPinned`,
`hasOpenOverlay`, `isDragging`. It ignores `isEditorFocused`, `msSinceLastKeystroke`, and
`isWindowKey`, behind a block marked PROVISIONAL.

This is invisible in M0 **because there is nothing to type into**. The moment a note editor
exists, a user typing while their cursor drifts off the panel loses it mid-sentence — the
exact failure spec §4.4 opens by naming.

**Resolved.** The policy now reads: hard invariants (pinned / overlay / dragging) veto
first; a focused editor vetoes outright, because losing what you are typing because the
mouse drifted is the worst failure this panel can have, and clicking into another app
clears focus anyway so it cannot strand the panel open; then a `typingGrace` window (2 s)
catches the case where focus has gone but the user is still working. `isWindowKey` remains
deliberately unused — a panel can be key from one stray click, too weak a signal to
suppress on — and the doc comment records that it was considered rather than forgotten.
Six new tests cover it, including the path through `reduce` at `.exitDwellElapsed`.

## 2. ~~There is no channel to feed those signals~~ — CLOSED `124f3bc`

`PanelController` exposes a setter for `isPinned` only. `hasOpenOverlay`, `isDragging`,
`isEditorFocused`, and `msSinceLastKeystroke` have no path from the SwiftUI layer into
`PanelContext` at all.

**Resolved.** `PanelViewModel` gained `isEditorFocused`, `lastKeystrokeAt`, `isDragging`,
and `hasOpenOverlay`; `PanelController` mirrors each with the same `withObservationTracking`
re-arm pattern already used for the pin. `msSinceLastKeystroke` is computed fresh when the
context is snapshotted, never stored as an ageing duration, so `PanelMachine` stays free of
clocks. `isDragging` and `hasOpenOverlay` are wired but have no producer yet — there is no
drag and no popover until M2.

## 3. ~~The Escape monitor swallows Escape application-wide~~ — CLOSED `124f3bc`

`PanelController`'s `addLocalMonitorForEvents` returns `nil` for **every** Escape key-down,
including while the panel is hidden. Inside an `NSTextView`, Escape dismisses completions
and exits find bars; none of that will reach the editor.

**Resolved.** The monitor now passes the event through when the panel is not expanded, or
when `panel.firstResponder` is an `NSText`, and only consumes-and-collapses otherwise.

## 4. ~~The purity guard cannot see a non-portable dependency~~ — CLOSED `fb3c5ac`, `c8f28b4`

`scripts/check-core-purity.sh` greps source `import` lines. It never reads `Package.swift`.

Spec §3 rule 1 exists so `NotebarCore` recompiles under Swift for Windows in M5. **GRDB
targets Apple platforms and Linux, not Windows.** Adding it as a direct `NotebarCore`
dependency would break the Windows strategy while the guard reports `core purity: OK`.

**Resolved, in two parts.** The persistence work put GRDB in a new `NotebarStore` target
behind the repository protocols, leaving `NotebarCore` with zero dependencies, and taught
the guard to parse `Package.swift` and fail if the `NotebarCore` target declares any
dependency at all (`fb3c5ac`). The logging work then found the guard still would not catch
`import os` — Apple-only, no Linux or Windows counterpart — so the always-forbidden list
grew to include `os`, `OSLog`, `Combine`, `CoreData`, `SwiftData`, and `CryptoKit`
(`c8f28b4`).

Both were caught the same way: an agent doing the right thing by judgement and then
reporting that nothing would have stopped it doing the wrong thing.

Two narrower holes in the same guard, both known:
- `@preconcurrency import AppKit` slips the `^import` anchor.
- A file with both a guarded and an unguarded import of the same module passes.

## 6. What is already shaped well for M1

- `PanelViewModel.selection` is model-owned (so the collapsed handle can read it), which is
  exactly where note-tab state belongs. Note tabs slot in without restructuring.
- GRDB repositories land in `NotebarCore`, where `swift test` already reaches — so no
  app-target test bundle is needed for the data layer.
- The pin control needs no state-machine work: `isPinned` is already an absolute veto in
  `shouldCollapse` and is covered by `pinnedSurvivesExitDwell`. It needs a button and a
  binding.

## 7. Outstanding, needs the human

- **Idle CPU under 1%** — the only Definition-of-Done item with no evidence of any kind.
- **The permanent handle sliver on other apps' fullscreen Spaces** — the direct cost of the
  discoverability the handle buys. Needs a verdict, not a fix.
